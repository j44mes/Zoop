# Page-analysis prototypes

Three compositions were drawn with the same sample page before the second pass was built. They share one palette. The difference is how the page is arranged.

## A — Summary deck

The page title, address, and target phrase sit across the top. The score and the three next actions sit side by side. Recommendations, checks, search appearance, and advanced details are tabs underneath.

This keeps the important numbers in view before any technical list, and it uses the width WordPress leaves beside its own menu.

## B — Persistent rail

Identity, the phrase, and the score stay in a left rail while the findings scroll on the right. The next action remains visible, but the rail repeats the action list and becomes cramped next to the WordPress menu. The primary buttons stack into a form.

## C — One task at a time

A single recommendation fills the page, with steps for the phrase, the score, and each finding. It is calm, and it hides the score, the address, and the rest of the checks until the user moves through the sequence.

## Choice

A is the one that was built. It has the clearest hierarchy at desktop width, it does not add a second sidebar, and the full diagnostic stays one tab away. B’s rail was the better reading pattern only when the window is already wide. C asks for too many steps before an experienced user can see what Zoop checked.
